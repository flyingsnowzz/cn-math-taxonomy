# M3 工程方案：账号、云同步、付费入口（暂不收款）

> 决策前提（2026-11-02 与负责人确认）：
> - 有公司主体；域名使用 **www.zyxw.cn（已 ICP 备案）**，不用 pansgo。
> - 登录三种：手机验证码、账号密码、微信（有认证服务号）。
> - **本阶段不接入支付**，只把会员权益判断的入口留好，种子期手动开通。

## 一、范围

**做**：后端服务、三种登录、计划/档案/错题云同步、会员权益字段与拦截骨架、埋点上报接口、账号设置页。

**不做**：微信支付/支付宝、自动续费、发票、订单系统。付费代码只到「权益判断」层，`entitlements` 由后台/管理手段手工发放。

## 二、总体架构

```
Vue 静态站（www.zyxw.cn，留在现有云服务器的 Nginx/静态托管，非腾讯云）
        │ HTTPS + JWT（api.zyxw.cn）
        ▼
API：腾讯云 CloudBase 云托管容器（Node 20 + Express + TypeScript，自动伸缩）
        │ VPC 内网
        ▼
TencentDB for PostgreSQL 16：账户关系数据 + jsonb 用户数据
        ├─ 账号：手机号+验证码 / 密码 / 微信 OAuth
        ├─ 埋点：events 表只追加
        └─ 权益：entitlements（手工发放）
```

技术选型：

- **接口层独立部署**：Express + TypeScript（长驻 HTTP 服务，生态成熟），`server/` 目录，node:test 单测，本地 `docker compose up` 起完整依赖。
- **PostgreSQL 16**：账户/权益是关系数据；用户业务数据（补救计划、盲区、孩子档案）放 `jsonb` 列，`(user_id,key)` 唯一约束 + `updated_at` 实现最后写入获胜；不使用云厂商专有数据库。
- **密码**：`node:crypto` 的 scrypt（内置、无原生模块）；验证码与限流用带 TTL 的 Postgres 表，种子期不引入 Redis。
- **部署（CloudBase 云托管）**：Express 打成标准 Docker 镜像部署到腾讯云 **CloudBase 云托管**，自动伸缩、按用量计费；PostgreSQL 用独立的 **TencentDB for PostgreSQL 16**（与云托管同 VPC 内网访问、自动备份，不放进可重建的容器）；**主站 www.zyxw.cn 保留在现有非腾讯云服务器**，仅把构建产物上传，前端通过 api 子域调接口；生产 HTTPS 由云托管网关负责。
- **备案接入（重要前置）**：zyxw.cn 现有备案在其他云厂商；api.zyxw.cn 解析到腾讯云前需在腾讯云做「新增备案接入」（不改变现有备案、不影响主站）。审核期间用 CloudBase 默认域名联调。
- **本地开发**：`docker compose up` 跑 Express + PG，与生产共用同一镜像/Dockerfile，仅 `DATABASE_URL` 等环境变量不同。
- 前端现有 Cloudflare Pages 保留为开发/预览；正式环境切国内托管（已备案域名解析境外主机在国内访问不合规也不稳）。

## 三、接口契约（v1）

除登录外均需 `Authorization: Bearer <token>`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /auth/sms/request | `{phone}` 发送验证码（限流：同号 60s 一次、每日 10 次） |
| POST | /auth/sms/verify | `{phone, code}` → `{token, user}`，未注册自动建号 |
| POST | /auth/password/login | `{account, password}` |
| POST | /auth/password/set | 登录后设置密码（账号=手机号） |
| GET | /auth/wechat/url | 取 PC 扫码授权地址（开放平台网站应用） |
| POST | /auth/wechat/callback | `{code}` 换 openid/unionid → 登录；未绑定则建号 |
| GET | /auth/wechat/mp | 微信内网页授权回调（服务号 snsapi_userinfo） |
| POST | /auth/bind/phone | 已登录后绑定/换绑手机（需验证码） |
| GET | /me | 用户资料 + entitlements |
| GET | /sync?keys=... | 批量取云端记录 |
| POST | /sync | `{items:[{key, data, updatedAt}]}`，逐项 last-write-wins（服务端 updatedAt 更新才覆盖） |
| POST | /track | 埋点批量上报（同现有 `cnmTrack` 事件结构） |

Token：JWT，7 天有效，刷新接口续期；密码用 argon2id 存储；短信验证码 5 分钟有效，存 Postgres 带 TTL 的表（不落日志）。

## 四、数据库与同步数据

核心表：

- `users(id, phone UNIQUE, password_hash, created_at)`、`user_identities(id, user_id, provider, provider_uid UNIQUE, unionid)`——手机/密码/微信多身份归一。
- `entitlements(user_id PK, member boolean, expire_at, source, updated_at)`。
- `sync_blobs(user_id, key, data jsonb, updated_at, PRIMARY KEY(user_id,key))`——下面每个本地键一行；服务端仅在 `incoming.updated_at > stored.updated_at` 时覆盖。
- `events(id, user_id, name, payload jsonb, created_at)`——埋点只追加。
- `sms_codes(phone, code, expires_at, consumed)`、`rate_limits(key, window_start, count)`。

同步的数据键（与现有 localStorage 对应）：

| 本地键 | 同步内容 | 冲突策略 |
|---|---|---|
| `cnmRemedy.plan.{subject}.v1` | 补救计划与复习状态 | 按 updatedAt 最后写入获胜 |
| `cnmBlind.local.v1` | 盲区台账 | 按知识点条目级取 updatedAt 最新（服务端合并） |
| `cnmChildren.v1` / records | 孩子档案与诊断历史 | 条目级合并 |
| `cnmTrack.v1` | 埋点 | 只追加，去重（客户端事件 uuid） |
| `cnmRemedy.shortfall.v1` | 缺题点 | 只追加 |

原则：本地仍是缓存，离线可用；登录后启动同步、之后每次写入防抖 2s 推送；拉取后与本地合并再写本地。

## 五、付费入口（不收款）

- `user.entitlements = { member: boolean, expireAt: string|null, source: string }`
- 前端新增 `useEntitlementsStore`，统一判断点：无限练习、AI 讲解、报告详细版、多档案等（规划 §5.1 的边界）。
- 免费用户照常走流程；到付费点显示「会员功能，即将开放」+ 留资（手机号已有），**不出现支付按钮**。
- 管理手段：种子用户由数据库直接置 `member:true`（或先做一个最简单的带 Basic Auth 的管理页）。

## 六、任务拆分

- **T3.0 契约与本地开发** ✅（2026-11-02）：本方案定稿；`server/` 骨架已落地——Express+TS、Postgres 迁移（users/identities/entitlements/sync_blobs/events/sms_codes/rate_limits 共 7 张表）、mock 短信/微信适配器、Dockerfile + docker compose（迁移自动执行）、健康检查与 5 个 node:test；`docker compose up` 端到端验证通过。
- **T3.1 账号基础设施**：users/identities 表、JWT 中间件、密码登录/设置密码、错误码与限流。
- **T3.2 短信登录**：腾讯云短信适配（签名/模板见清单），验证码下发与校验、开发环境固定码 `123456`。
- **T3.3 微信登录**：开放平台扫码 + 服务号网页授权两条；unionid 合并；未注册自动建号。
- **T3.4 前端账号层**：auth store、登录/注册页（三方式）、会话保持、退出；未登录体验不降级。
- **T3.5 云同步**：sync 接口 + 前端同步引擎（合并/防抖/冲突时间戳），现有 store 接入；断网回退本地。
- **T3.6 埋点上报**：`utils/track.ts` 增加 transport（登录后批量上报，未登录仍本地）。
- **T3.7 权益骨架**：entitlements store + 付费点拦截 UI（「即将开放」），管理端手工开通。
- **T3.8 部署**：Express Dockerfile（多阶段构建、非 root 运行）、CloudBase 云托管服务与环境变量/密钥、同 VPC 的 TencentDB PostgreSQL（参数、内网访问、每日备份）、前端构建产物同步到现有主站服务器、api.zyxw.cn 备案接入后绑网关与 HTTPS、生产验收清单。

每个任务都要有：接口/类型定义、node 单测或 e2e、不破坏现有 102 个 e2e 与 44 个单测。
